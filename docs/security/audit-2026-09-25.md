# Homelab Security & Attack-Surface Report

**Target:** mini PC `debian` (Debian 13.7, kernel 6.12), reached via Tailscale `100.75.146.21`
**Date:** 2026-09-25 · **Method:** read-only recon over SSH + unauthenticated external probes of public tunnel hostnames. No changes made, no credentials used, no exploitation.

**Note:** LAN route to `192.168.15.126` was dead during the audit (`No route to host`; `debian.local` now resolves to the stale `.131` lease). Audit ran over Tailscale.

---

## Attack surface, three tiers

1. **Public internet** — Cloudflare Tunnel publishes **28 hostnames** on `*.davideghiotto.it`.
2. **Tailnet** — box is a Tailscale node (`ShieldsUp=false`); the tailnet includes a **second user's** devices (`ilai5800@` — the NAS owner: `dxp4800pro-21af`, `iphone171`).
3. **LAN** — `192.168.15.0/24`.

---

## Headline finding — UFW does not protect the published container ports

UFW is enabled (`DEFAULT_INPUT_POLICY=DROP`), which suggests only SSH is reachable. **It is not.** Docker's `-p` publishing inserts rules into the `DOCKER`/`nat` iptables chains that are evaluated *before* UFW's `INPUT` chain, so **every published container port bypasses UFW entirely.** ~30 services are bound to `0.0.0.0` and are reachable from the whole LAN **and** every tailnet peer (including the other user's devices), regardless of UFW.

Ports open on `0.0.0.0` (LAN + tailnet reachable):

| Port | Service | Note |
|---|---|---|
| **11434** | **ollama** | **No authentication.** Anyone on LAN/tailnet can run models, pull/delete them, use the GPU. |
| **4000** | litellm | API needs key (good), but reachable |
| 3080 | open-webui | verify signup is disabled |
| 3000 | dokploy | orchestrator UI on all interfaces |
| 3001 | grafana | |
| 3003 | hub | |
| 8080 | qbittorrent / Swarm UI | |
| 5055 | jellyseerr/seerr | |
| 7878 / 8989 / 9696 / 6767 | radarr / sonarr / prowlarr / bazarr | *arr web UIs |
| 5000 / 4567 / 4571 | kavita / suwayomi / manga | |
| 8096 / 8097 / 8898 | jellyfin-proxy / jellyfin / cinema | |
| 6881 | qbittorrent BT | intended (port-forwarded) |
| **2377 / 7946 / 4789** | **Docker Swarm control plane** | mgmt plane on all interfaces |

**Fix:** filter the Docker chain, not just INPUT. Add a `DOCKER-USER` rule that drops external traffic except from trusted sources, e.g.:
```
iptables -I DOCKER-USER -i enp3s0 ! -s 192.168.15.0/24 -j DROP   # example — adjust
```
Better: bind ports that only the host/tunnel need to `127.0.0.1:` in each compose (`127.0.0.1:11434:11434`), so nothing but the box itself can reach them. **Ollama and the Swarm control plane should not be on `0.0.0.0`.**

## Public tunnel exposure (verified externally, GET only)

**Protected by Cloudflare Access** (good — 302/403 to `cloudflareaccess.com`): `monitoring`, `jarvis`, `loki-push`, `deploy-cassette`.

**Open to the internet, relying on app-level auth only:**
- `llm` (litellm): `/health`, `/ui/`, `/openapi.json` served unauthenticated; `/v1/models` correctly 401. Login page and full API schema are public.
- `openui` (open-webui): `/api/config` public, leaks version. **Confirm signup/registration is disabled** or anyone can create an account.
- `streaming` (jellyfin): `/System/Info/Public` leaks server name `nasilario` + version `12.1.0`.
- `netflix` / `discover` (seerr): `/api/v1/status` leaks version `3.4.1`, `/settings/public` leaks config.
- `wedding-admin`, `manga`, `home-cinema`, `maestro`, `cassette`, `ytzero`, `atlante`, `thumb`, `finance`, `ral-api`: 200, public web apps. **`wedding-admin` is an admin UI on the open internet** — confirm it enforces auth.
- `riddle`: 401 (auth enforced — good).

**Consider** putting the management/admin surfaces (`llm`, `openui`, `wedding-admin`, and the *arr/qbit UIs if ever tunneled) behind Cloudflare Access like `monitoring`/`jarvis` already are.

### Unanchored tunnel path regex on the `deploy-*` hostnames
The deploy hostnames restrict the tunnel to `api/compose\.(deploy|one)`, but the regex is **not anchored**. A path such as `/xapi/compose.one` matched and reached the **Dokploy web app** instead of being 404'd at the edge. The real endpoint `/api/compose.one` still returns `401 Unauthorized` (Dokploy token required), so this does **not** grant deploy access — but it defeats the intent of exposing a single path and widens what an attacker can poke at.
**Fix:** anchor the ingress path, e.g. `^/api/compose\.(deploy|one)$`.

## Docker / container hardening

- **Raw `docker.sock` mounted into `homelab-alloy` (Grafana Alloy).** A read-only bind (`:ro`) only stops replacing the socket file — it does **not** stop write API calls over it. A compromise of Alloy = full Docker API = host root. Alloy is a log shipper and needs no write access. **Use the `socket-proxy` pattern already in place for `hub-docker-proxy`** (read-only, filtered API).
- `dokploy-traefik` also mounts raw `docker.sock` (`:ro`) — same caveat; expected for Traefik but note the risk.
- `dokploy` mounts `docker.sock` **rw** — by design (orchestrator), highest-value target on the box.
- **`homelab-cadvisor` runs `privileged=true`** with `/` mounted — root-equivalent; expected for cadvisor but it is a full-host-access container.
- **Internet-adjacent containers running as root:** `litellm` (public via tunnel) and `open-webui` run as `user=root`/`0:0`. On an RCE they give root *inside* the container. Run them as a non-root UID.
- `node-exporter` (`net=host pid=host`, `/:/host:ro`) — standard, low risk.
- Traefik static config has `api.insecure: true` (dashboard), but it is only on `dokploy-network`, not published — low.

## Host hardening

- **SSH `PasswordAuthentication` is still enabled** (Debian default; never overridden in `sshd_config.d/`). Brute-force surface. `fail2ban` sshd jail is active (mitigates), but keys are already deployed — set `PasswordAuthentication no` and `KbdInteractiveAuthentication no` (latter already set). Matches the existing `TODO-hardening.local.md`.
- `X11Forwarding yes` on a headless server — set to `no`.
- **36 pending apt updates**, including security (`bind9-*`). `unattended-upgrades` is installed and active, but run `apt full-upgrade` to clear the backlog now.
- `kernel.kptr_restrict=0` — kernel-pointer leak; set to `1`.
- Minor: `net.ipv4.conf.all.send_redirects=1`, `rp_filter=0` — tighten in a sysctl drop-in.
- `auditd` not installed (optional, for audit logging).
- Tailscale: `ShieldsUp=false` and a second user's devices share the tailnet — everything on `0.0.0.0` is reachable to them. Consider Tailscale ACLs to restrict which peers reach the box, or `ShieldsUp` + explicit allows.

## Priority order

1. **Filter Docker-published ports** (DOCKER-USER rule) and/or bind internal services to `127.0.0.1`. Close **ollama:11434** and the **Swarm control plane** first. *(biggest gap — UFW gives false confidence)*
2. **Move Alloy to the socket-proxy** (drop raw `docker.sock`).
3. **Disable SSH password auth**; run pending security updates.
4. **Anchor the `deploy-*` tunnel path regex.**
5. Put admin web surfaces behind Cloudflare Access; confirm `open-webui` signup and `wedding-admin` auth.
6. Run `litellm`/`open-webui` as non-root; set `kptr_restrict=1`, `X11Forwarding no`.

**Not vulnerabilities (working as intended):** Cloudflare Access on monitoring/jarvis/loki; litellm master-key on `/v1/*`; riddle auth; fail2ban; UFW default-deny (just doesn't cover Docker); `hub-docker-proxy` socket-proxy pattern.
